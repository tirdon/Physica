Design notes

Animations are values

Notes on the framework behind these demos — deferred animations, an append-only timeline, and one language from TeX to vertex buffer.

This is how the pendulum demo hangs its bob and starts it swinging, condensed from the real script:

let pivot  = Wall(face: .down)             // the ceiling
let center = pivot.center
let string = Line(start: center, end: center - 4.j)
let bob    = Circle().move(to: string.end)

scene.add(pivot, string, bob)
scene.play(bob.move(to: 1.i + 1.j), for: 2.s)
scene.play(.write(formula), for: 2.5.s)    // θ̈ = −(g/ℓ) sin θ

The odd thing about move(to:) is that it moves nothing. Every entity method in Physica — move, shift, rotate, fade, morph — returns an Animation: a description of a change that hasn't happened yet. Descriptors chain (star.opacity(0.8).shift(-1.j) is one value carrying two changes) and touch nothing until the scene accepts them. The snippet already leans on this: bob isn't a circle, it's a circle carrying its pending move. scene.add lands it at the string's end once, and the later play re-animates the same handle without double-applying that move.

That one decision — animation as a value rather than a side effect — is the framework's spine. Nearly everything these demos do that a tweening library can't falls out of it.

A history, not a schedule

Most animation systems are schedulers. You register callbacks against a clock, the clock fires them, and a fired tween is gone. Physica's timeline is instead an append-only history of clips, and every track in a clip honors one contract: begin captures start values, apply(at:) is a pure function of time, rewind puts things back. Seek forward and clips apply in order. Seek backward and they rewind in reverse — a title introduced by .write un-writes, then stops existing. .erase isn't separate code; it's the write blueprint run backwards: the fill fades, then each stroke retracts, last glyph first.

Scroll-driven stories are the payoff. A Story owns no second engine; it partitions the one timeline into slides and steps and hands the playhead to your scrollbar. Scroll down the wave-interference explainer and the lesson plays; scroll up and it plays backwards: graph morphs, camera moves, equation writes and all. Nobody wrote a reverse path for any of it.

One currency, so everything composes

Because Animation is the single currency, unrelated features animate identically. The camera is an entity, so a slide transition is scene.play(scene.frame.zoom(to: 7)). Text slices to glyphs: formula[(formula.glyphCount - 4)...].color(.teal) tints exactly the sin θ in the pendulum's equation of motion. Even chart data is animatable — in the string slide of the wave story, string.plot { -mode($0) } swings a plotted standing wave to its mirror image by morphing the sample polyline.

Swift from TeX to vertex buffer

The other bet is vertical. Apart from MathJax, which lays out the TeX, no JavaScript runs under these pages — no animation library, no charting library, no physics engine. The equation the pendulum writes overhead comes back from MathJax as SVG and is Swift from there down: an SVG-path parser (arcs lowered to cubics), a TrueType parser for the fonts, a small computer-algebra system with exact rational arithmetic for the equation game, a symplectic rigid-body integrator stepping at a fixed 1/240 s for the toon-shaded drop, and a WebGPU renderer — all compiled to WebAssembly.

The renderer stays deliberately dumb: it consumes flattened scene snapshots and knows nothing else. That seam keeps the framework honest, because everything above it runs on macOS with no GPU and no browser. The test suite plays stories, scrubs them backwards, and drags tokens across equals signs; 442 tests finish in under half a second.

The lane that doesn't scrub

Interaction gets one deliberate exception. In the equation-game story, dragging a projection operator onto the vector equation F = mg + T runs through interact: the same clip machinery, played immediately, in parallel — and kept out of the scrub history. Your algebra survives while the lesson rewinds around it. A timeline you can trust records what it owns and nothing else.

The demos above are the argument — each mounts with one statement, Storytelling { … } for the scenes and stories, Document("…") { … } for the article. Open the wave story, scroll a few slides in, and drag the scrollbar back up. The test of an animation system isn't what it plays. It's what it plays backwards.
