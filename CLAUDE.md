## Big picture

Pure-Swift-6 SwiftWasm framework: RealityKit-style ECS + Manim-style scripted animation + WebGPU rendering + Hamiltonian rigid-body physics. Two targets, one boundary that is now a *subtree*, not a target split:

- **`Sources/Physica/`** — the whole framework. Everything outside `WASM/` is dependency-free (never imports Foundation or JavaScriptKit), builds and tests on macOS, and is where almost all logic and all tests live. **`Sources/Physica/WASM/`** (`Render/` + `Web/`, every file `#if os(WASI)`) is the WebGPU renderer and browser glue; it links JavaScriptKit through a `.when(platforms: [.wasi])` conditional dependency, so host builds stay JSKit-free. The seam is unchanged: `Scene.snapshot()` → `SceneSnapshot` (flattened world-space primitives) and the `RenderBackend` protocol — host tests assert snapshots via `MockRenderBackend`; the renderer is a dumb consumer. `WebRuntime.run(engine:scene:)` is the one-call browser bootstrap (renderer + playback controls + input + visibility observer + debug overlay + rAF loop; logs the timeline first so GPU-less smoke runs still print it).
- **`Sources/PhysicsEngine/`** — thin wasm executable: entry point, `App.swift`, and `Demos/`. `App.boot` branches on `globalThis.physicaStory`: set (only `story.html` sets it) → `EquationStoryDemo` + `StoryRuntime`; unset (incl. Bun smoke, which has no DOM) → `PendulumDemo` + `WebRuntime`, byte-identical to before. Files using `JSPromise.value()` must `import JavaScriptEventLoop` explicitly — the async helpers live in that module, and Swift's lenient member-import visibility used to mask it.

`Math/TypeAtlas.swift` defines `Real` (`Float` on wasm, `Double` on macOS), `Position = SIMD3<Real>`, and the libm shims (`Real.sin` etc. — Apple's simd module doesn't exist on WASI, hence the hand-rolled `Quaternion`/`Matrix4`). Write numeric code against `Real` and keep test assertions tolerance-based.

### Concurrency model (load-bearing, applies everywhere)

The whole mutable object graph (`Entity`, `Scene`, `Timeline`, `Animation`, `Engine`, `System`, web glue) is `@MainActor`; beneath it is a pure `Sendable` value layer (Transform, Path, Mesh, Color, snapshots, event enums). Conventions that exist because of this:

- `Component` is deliberately **not** Sendable (`UpdaterComponent` stores `@MainActor` closures).
- `Entity.id` is a `nonisolated let UInt64` from a monotonic counter (deterministic for tests; no UUID/Foundation); `==`/`hash` use id only.
- MainActor classes expose `var debugString: String` instead of `CustomDebugStringConvertible` (which is nonisolated). Tests assert on `debugString`, formatted with the hand-rolled fixed-decimal `fmt()` so Float/Double hosts print identically.
- AsyncStreams (`Timeline.eventStream()`, `Scene.inputStream()`) carry Sendable enums only.

### Swift performance (conventions)

Dispatch/ARC levers are applied once and meant to stay. **Every leaf class is `final`** (devirtualization + inlinability) — only the six deliberately-`open` bases (`Entity`/`Group`/`Layout`/`PathEntity`/`SampledPathEntity`/`MeshEntity`) are subclassable. The `Real`/libm shims in `Math/TypeAtlas.swift` are `@_transparent` (inline at every call site, no Float/Double wrapper frame). Hot array builders `reserveCapacity` from a known count (`Mesh`, `Font`, `SampledEntities`, `MeshMorph`, `PathFlatten`, `GeometryUploader.appendMesh`). **`borrowing`** rides only the per-frame hot paths where a *heap-backed* value is read-only — `GeometryUploader.pack`/`appendMesh`/`appendPath`/`appendFill`/`appendStroke` (`SceneSnapshot`/`MeshDraw`/`PathPrimitive` each carry arrays) and `MeshMorph.resampleByDirection`/`farthestHit` (`Mesh`) — eliding the retain/release of the contour/vertex buffers per primitive. It is **deliberately not** put on trivially-copyable structs (`Transform`/`Matrix4`/`Quaternion`/`Color`/`Position` — no ARC, so WMO already elides the stack copy) nor on the once-per-frame `RenderBackend.render` witness (changing its convention would ripple to the protocol + `MockRenderBackend` to save a single retain). **`consuming` and `sending` are evaluated-but-unused on purpose:** the value graph keeps canonical data in blueprints/components and hands *copies* to tracks (the source outlives the call), and setters read a value twice, so `consuming` would force explicit `copy`s for zero gain at cold construction time; `sending` is obviated by the concurrency model — AsyncStreams carry Sendable enums and JSClosure bodies use `assumeIsolated`, so no non-Sendable value crosses an isolation boundary to transfer. The 18 `@escaping` closures are all genuinely-stored `@MainActor` callbacks (components/tracks/web listeners) — correct as written; non-escaping is the default everywhere else.

### Animation = the currency type

Entity methods (`move/shift/scale/rotate/color/fade/opacity/morph`) are **deferred descriptors** — they return an `Animation` and mutate nothing. Chained calls accumulate (`star.opacity(0.8).shift(-1.j)` carries both blueprints as `AnimationPair`s); `scene.add` marks pair ids consumed and `play` filters them, which is why a stored handle (`let bob = Circle().move(to: p)`) can be re-animated without double-applying its original move. `scene.add`, `scene.play`, `scene.wait`, `scene.pause(System.self)` all enqueue clips and also return `Animation`, so everything composes. Play forms: variadic `play(_:for:easing:)`, `play(group:)`, builder `play(3.s) { ... }`, and composer `play { clip in clip.add(anim, for: 1.s, offset: ...) }` (one clip, per-animation timing). Duration precedence: `play(for:)` > `animation.duration` > blueprint default (1 s).

Write/draw/erase/highlight are **static `Animation` factories**, not entity methods: `scene.play(.write(title))`, `.draw(shape)`, `.erase(shape or title)`, `.highlight(entity)`. They resolve via a concrete `play(_: Animation...)` overload (leading-dot syntax can't see statics through `any Animatable`). Write/draw blueprints set `introducesTarget`, so `play` auto-adds the entity — no `scene.add` first; erase is the same blueprint `reversed` (value 1→0, fill fades then stroke retracts, last glyph first) plus `removesTargetAtEnd`, which drops a `RemoveEntityTrack` at the pair's end time. Both are scrub-safe: rewinding un-adds / re-inserts at the original root index (painter's order survives). An explicit `scene.add` earlier keeps ownership — the play-clip auto-add only claims entities absent at clip begin.

`.highlight(entity, color:padding:)` is a neon border chase (loading-loop): a transient rounded-rect `PathEntity` is built around the subject's bounds at clip begin, the stroke head runs one lap (`strokeProgress`) while the tail follows (`strokeStart`, head window 62%, tail leaves at 38%), and nothing remains at the end — `introducesTarget` + `removesTargetAtEnd` on one blueprint. Because the border is introduced and removed by the *same* clip, `RemoveEntityTrack` resolves its root index lazily in `apply` (at `begin` the AddEntitiesTrack hasn't inserted it yet).

`saveState()` / `restoreState()` (Manim's save_state/Restore) work on any Animatable and on `Group` bags (members): save is a **0-duration clip** that captures transforms at that point of the *timeline* (begin-captured — the state usually only exists during playback, e.g. mid-swing), stored in `SavedStateComponent`; restore animates `entity.transform` back to it via `PropertyTrack<Transform>` (no capture → no-op). Scrub-safe: rewinding past the save removes/restores the component. Note a clip sitting at t = X stays applied when you seek exactly to X — "before the clip" means strictly earlier.

Text/formula glyph slices: `title[0]`, `title[1..<4]`, `formula[(n - 4)...]` return a `GlyphSlice` with `color(_:)`, `color(mix: [Color])` (multi-stop ramp across the slice) and `fade(to:)`/`opacity(_:)` — deferred Animations targeting the parent entity. Per-glyph overrides live on `PositionedGlyph` (color/opacity), beat the entity style in the snapshot, and rewind to their prior values exactly (a nil override comes back as nil). Out-of-range slices clamp to no-ops. Entity-level `color(_:)` animates the shared `RenderStyleComponent` instead; `text.color(mix:)` is the whole-text gradient. Note `(n - 4)...` needs the parens — postfix `...` binds tighter than `-`.

### Math (MathJax → SVG → Path)

Math formulas are `TextEntity`s, so write/erase/morph apply unchanged. Core side (host-testable): `Path.svg(d)` parses SVG path data (full command set, arcs lower to cubics), `MathSVG.glyphs(fromSVG:)` walks MathJax tex-svg markup (defs/use/g-transform/rect; each `<use>`/`<rect>` = one glyph, document order = stagger order; output em units, y flipped back up, centered on bounds), `TextEntity.math(svg:fontSize:color:)` wraps it. Web side: `MathJaxLoader.formula("\\frac{g}{\\ell}", fontSize:)` injects `tex-svg.js` from jsDelivr (`crossorigin` — COEP needs the CORS headers) with **`fontCache: "local"`** (global cache would put glyph defs outside the svg and `MathSVG` throws `unknownReference`), polls for `MathJax.startup.promise`, then `tex2svg(...).querySelector("svg").outerHTML`. No DOM (Bun smoke) → `.unavailable`, demo skips math. Test fixtures in `MathSVGTests` are genuine mathjax-full output — regenerate with bun + `mathjax-full` if MathJax structure ever drifts.

### Mesh shading and path textures

`mesh.shaded(.toon)` (= `.toon(bands: 3, outline: 0.035)`) quantizes diffuse into flat bands and adds an inverted-hull outline; `entity.textured(.chalk / .pencil)` applies procedural grain to any path-producing entity (shapes, text, math). Both ride the spare `params` vec4 in the 256-byte per-draw uniform slot (paths: x = texture mode 0/1/2, 3 = blackboard backdrop quad, yz = grain seed; meshes: x = shading, y = bands, z = outline inflate) — core carries them via `MeshDraw.shading` / `PathStyle.texture`. Gotchas: our UV-grid meshes wind outward faces **CW**, so the outline pipeline culls `"back"` (not `"front"`) to drop the hull's camera side; hard-edged meshes (box) crack at corners when inflated — keep outlines on smooth surfaces. Texture noise samples `world − seed` where the seed is the entity's position (`PathStyle.textureSeed`, set in the snapshot pass), so grain rides a moving entity instead of letting it swim through world-pinned static; the blackboard quad keeps plain world coords.

Strokes draw the **trim window `[strokeStart, strokeProgress]`** of the path's total arc (continuous: whole quads + fractional quads on both boundary segments — integer-only capping pops whole sides on low-vertex shapes). Write/draw/erase only move the head; highlight moves both. `style.neon` makes the uploader emit two stroke commands over the same window: a 3× wide translucent glow in the tube color under a whitened core. `StrokeCap` (`RenderStyleComponent.cap` / `stroke(_:width:cap:)`): `.square` (default — ends extended by half width, seals joints), `.butt` (exact ends), `.round` (no extension; discs at run starts and every quad end seal joints and round visible ends — the highlight uses it).

`RenderStyleComponent.strokeWidth` is **normalized 0...1**: 1 = 10% of the frame's longest side, resolved to world units in `Scene.snapshot()` (clamped, `PathStyle.strokeWidth` carries the result). At the default fit-10 camera the factor is exactly 1, so values read like world units there. `scene.size` is the visible frame's world size (logged to the console at boot).

`scene.background = .color(c)` drives the clear color; `.blackboard` (= `.blackboard(tint:)`, deep-green slate) additionally draws a fullscreen flat quad (params.x = 3: value-noise smudge + chalk dust, world-anchored) before meshes/paths — it rides `SceneSnapshot.background` + `snapshot.frame` (the camera's visible rect sizes the quad).

### Plotting (Plane / graph / field / streamlines)

`Plane(x:y:gridStep:subdivisions:size:…axis:font:)` is a `Group` of `plane.subgrid` (minor half-step lattice, `subdivisions` per cell, default 2; `subdivisions: 1` disables) under `plane.grid` (`PathEntity` major lattice), `plane.axes` (a `Group` of `plane.xAxis`/`plane.yAxis` — **real `Arrow` entities**, `doubleHeaded` so a tip sits at both terminals; grab and adjust `start`/`end`/`headLength`/`doubleHeaded`/style directly — plus `plane.ticks` `PathEntity`), and `plane.labels` (a `Group` of `plane.xLabels` + `plane.yLabels` sub-groups holding shown `TextEntity` ticks — built only when a font is given at init or assigned via `plane.labelFont`; reveal with `scene.add(plane.labels)`, since `.draw` is PathEntity-only and `.write` is single-TextEntity). `Group` has an Int subscript for child access in add order — `plane.xLabels[0].color(.red)`, `plane.axes[0] === plane.xAxis` — trapping out-of-range like Array. `plane.originLabel` is the "0" below-left of the axis crossing (`TextEntity?` — nil without a font, when `showLabels`/`showOriginLabel` is off, or when the ranges don't contain zero — an edge-hugging crossing isn't the origin). `AxisOptions` (top-level struct, **not** nested — nested types in @MainActor classes inherit isolation) holds overhang/tickLength/tipLength/showTicks/showLabels/labelSize; assigning `plane.axis` (or `labelFont`) rebuilds the board in place **re-applying options over direct arrow tweaks**; `tipLength: 0` → `Arrow` degrades to a plain line (headLength ≤ 1e-6 skips both head polygons — a general Arrow behavior now; `Arrow`'s stroke cap also defaults to `.round`, softening the tip). `point(x, y)` maps data → world (default 1 data unit = 1 world unit); rescale with chainable `.size(w, h)` / `.size(w, aspect:)` **before sampling** (`aspectRatio` reads back w/h). Tick access for custom annotations: `xTickValues`/`yTickValues` + `tickPoint(x:)`/`tickPoint(y:)` (world points on the axis lines). `graph.value(at: x)` / `graph.point(at: x)` read the **live** polyline (mid-morph included) — pair with an updater (`dot.updater = { $0.position = wave.point(at: 1.2) }`) for annotations that track an animating curve. `plane.graph(of:samples:)` / `plane.plot(points)` / `plane.field { p in ... }` / `plane.streamlines { p in ... }` return **standalone entities** sampled in plane space (they copy the plane's transform at creation — position the plane *before* sampling): reveal via `scene.add` / `.draw`, move together with an explicit `Group(plane, graph).move(...)`, never `scene.add` a plane child you also `.draw`. **Data is the animatable**: each entity's `.plot(...)` returns an Animation — graphs/streamlines lerp sample polylines via `PolylineMorphTrack` (index-paired, arc-length resample to the larger count; no contour sorting, unlike `PathMorph`, which would scramble many-line bundles), fields lerp `vectors` and rebuild arrows per frame so heads point true mid-morph. Topology stays constant by construction: function graphs re-sample the same xs, streamlines re-integrate the same seeds/steps (RK2, step clamped to gridStep/2, lines freeze at the board edge), fields always emit shaft + head contours even degenerate (heads are *closed* triangles and the field style is `isFilled: true`, so heads render solid — the open shaft contours have no area and the fill skips them). Graph y-values clamp to the y range; non-finite samples pin to the top edge; arrow length saturates (`maxLen·m/(m + reference)`, reference = creation-time mean magnitude, deliberately not renormalized on re-plot).

### Frame and camera

Default camera is `.orthographicFit(extent: 10)`: the longest visible side is 10 world units (aspect 1.6 → 10 × 6.25; portrait → 10·aspect × 10). `move(to: Unit)` resolves against this frame at clip start and pins that entity's own bounds to the edge — separate calls in one play each move independently (no implicit grouping; user decision 2026-06-11). To move entities together, wrap them: `Group(pivot, string, bob).move(to: .bottom)` (`GroupedMoveToUnitBlueprint`) pins the union of the members' bounds and shifts every member by one shared delta, so a pendulum keeps its string length. The group works as a transient bag — it never joins the scene; its `Animatable...` init also accepts stored handles (`let bob = Circle().move(...)`), and `Group.addChild` only overwrites a child's scene pointer when the group itself is in a scene. Wall defaults sit just inside the frame (ceiling/floor y ±2.9, sides x ±4.6). Bodies outside **3× the frame** are frozen by `HamiltonianSystem` (no integration, no contacts) — physics integration tests use a big explicit camera (`PhysicsTests.makeWorld`) to stay clear of the cull. The Shift overlay culls labels outside the viewport and skips ~0-opacity entities. Two modes share the DOM `DebugOverlay`: **Shift** = `collectDebugLabels()` (one centered index per *top-level* entity — every group, equation/plane/chip/plain `Group`, collapses to a single label rather than unfolding its children into a `0.0`/`6.0.0` thicket; `snapshot(includeDebugLabels:)` reuses this same source); **Option+Shift** = `collectInteractiveDebugLabels()` (only draggable/touchable entities), aimed at equation elements so each token gets its own label instead. Interactive labels are a flat sequential number (no dotted path) carrying an `InteractionKind` (drag/drop/tap/doubleClick/hover) that the overlay renders as a **color** (per-kind `overlay-label-<kind>` CSS class) rather than text. `InputBindings`/`StoryRuntime` recompute `engine.isDebugOverlayActive` / `isInteractiveOverlayActive` from the live `shiftKey`/`altKey` flags on every key event, so the modes hand off as Option is pressed/released under Shift.

### Scrub-safe timeline contract

The timeline is an append-only clip history. Every track implements `begin(in:)` (idempotent start-value capture) / `apply(at:in:)` (pure in t) / `rewind()`. `seek` forward applies intermediate clips at their end time; backward calls `rewind()` in reverse (so entities added by an `add` clip disappear when you scrub before it). During seek all systems are suspended and one updater pass runs after. **System-driven state (pendulum, physics) intentionally freezes during scrub — it is not replayed.** Any new track type must honor begin/apply/rewind or scrubbing breaks; snap exactly to endpoints at t≤0 / t≥1 (see PathMorphTrack).

Per-frame order in `Scene.update`: paused-gated {timeline.advance → systems} → `interactions.advance` (**always**, outside the gate) → layouts → updaters. Updaters (`entity.updater = {...}` or `entity.bind(\.end, to: bob, \.position)`) also run once after every seek.

### Interactions & drag (parallel, pause-independent)

Two subsystems run *outside* the paused gate so they work while the timeline rests paused (story mode rests paused at every step boundary, exactly when the user interacts):

- **`scene.interact(...)`** (`InteractionRunner`) reuses `AnimationClip` wholesale but plays it NOW, in parallel, and **not in the scrub history**: `seek` never touches it, and structural effects it introduces (a triggered `.write`'s entity, an appended equation row) persist across scrubs — same policy as system-driven physics state. `InterruptionPolicy.complete` (jump to end — default; game results must land) / `.cancel` (rewind). `interruptAll` fires on slide change only. Same surface as `play` (moves, write/draw/erase, highlight, `.shake`); the concrete `interact(_: Animation...)` overload resolves leading-dot factories. Shared `bakeClip` means `play` and `interact` filter `consumedPairIDs` identically (only `add` inserts).
- **`scene.drag`** (`DragCoordinator`) is event-driven from `Scene.dispatch` (**not** a registry System — systems skip while paused). State machine press → (past `tapSlop`) drag → drop; a release within slop is a tap. Components are non-Sendable so they hold `@MainActor` closures: `DraggableComponent` (`payload`, optional `makeDragProxy` ghost so the source stays put, `snapsBack`, `onTap`/`onDragBegan`), `DropTargetComponent` (`accepts`/`onDrop` → `DropResolution.accepted/.rejected`/`onHoverChanged`), `TapComponent` (chips — works even while `drag.isEnabled == false`), `HoverComponent` (`onHoverChanged(entity, over)` — fired on idle bare-pointer enter/leave, tracked separately from the drag's drop-target hover; mouse/pen only since a lifted finger emits no moves; the web shell forwards idle `pointermove` and clears via `drag.clearHover()` on `pointerleave`), and `DoubleTapComponent` (`onDoubleTap(entity)`, also live while `drag.isEnabled == false`). Hit-test is own painter's-order traversal, **last-painted wins** (matches the renderer), manual world-XY containment. A rejected/off-target drop snaps home via an interaction (`.complete`); `cancelActive` is an instant restore (slide change). `.shake(_:)` is a static `Animation` factory (damped horizontal wobble, scrub-safe, exact at both ends), like `.highlight`. Double-click rides a dedicated `InputEvent.doubleClick(Position)` (the browser does the timing via DOM `dblclick`; the core carries no clock); `DoubleTapComponent.highlightSelf()` is the prebuilt "double-tap me to neon-loop my own bounds" handler (runs on `interact`, so it works while a story rests paused).

### Camera as an entity

`scene.frame` is a `SceneCamera: Entity` proxy (never joins the graph) whose `transform`/`zoomExtent` write through to `scene.camera`. Animate it with the ordinary blueprints — `scene.play(scene.frame.shift(...), scene.frame.zoom(to: 7), for: 1.s)` — so camera moves are normal scrubbable clips (story slide transitions for free). `zoom(to:)`/`focus(on:margin:)` are the only camera-specific blueprints; `move(to: Unit)` is `@available(unavailable)` (self-referential). Prefer `shift`/`zoom` over `move(to: Position)` for transitions — an absolute move drags z from 10→0.

### Story mode (ScrollTrigger)

`Story(scene:)` partitions ONE scrubbable timeline into slides: `story.slide(title, transition:) { s in … }` snapshots `timeline.duration` before/after the content to record `[startTime, endTime]` + deduped `stepBoundaries` (a 0-duration `add` collapses into the surrounding boundary). Content is **slide-scoped**: a slide's own-introduced entities auto-clear when the viewer advances to the next slide (a deferred zero-duration `SlideClearTrack`, computed as introduced − `s.carry` − in-slide removals); `s.carry(x)` keeps specific content past the slide (persists onward until an explicit `s.clear`), `s.clear(x)` drops it mid-slide, and globals (`scene.add`ed before/between slides) are never in a slide's own set so they persist untracked. The last slide never auto-clears — its board stays. `story.action(label, id:) { s in … }` registers a button that animates in parallel (via `interact`). `StoryPlayer` is the **single writer to the playhead** — story mode never `resume()`s, so systems stay frozen and the scripted clips carry all motion. Navigation rides one precomputed `Beat` list (time + slide + step) built once from the slides: `nextStep`/`previousStep` move ±1 beat, `nextSlide`/`previousSlide` jump between step-0 beats, and the slide index comes from the landed beat — identity is the beat, so there is a single `seekEpsilon` (scroll-scrub dedup) and no boundary-equality dance. A deferred-clear slide gets a rest one `boundaryNudge` *before* its end (so it shows fully built before the clear fires at the boundary); a clean boundary rolls straight into the next slide. Scroll → `scrub(...)`; arrows tween forward (advanced by `tick(deltaTime:)` with an exact snap onto the beat — the camera transition plays) and seek back instantly. Every move funnels through one private `apply(time:)` that seeks, dedupes, and runs the **slide-change hook** (`interactions.interruptAll` + `drag.cancelActive` + `.slideChanged`). Web: `StoryRuntime.run(engine:story:)` mirrors `WebRuntime` (logs the story first for smoke) plus per-slide scroll spacers (`height = max(minPx, pixelsPerSecond·duration)`), 4-arrow keydown (`preventDefault`), a horizontal-swipe recognizer for touch step-nav, action buttons, and a RAF loop that ignores scroll input while a tween drives the scrollbar (echo-safe). `story.html` is separate (`#story-pin` sticky, spacer track, `globalThis.physicaStory = true` before init); `index.html`/smoke untouched.

### Algebra & the equation game

`Sources/Physica/Algebra/` is dependency-free, host-tested: exact `Rational`, `indirect enum Expression` (incl. `.vector` — the extension Equalynx lacks), byte-level `Expression(parsing:)` (TeX-ish: `\vec`, `\frac`, `\cdot`, `\theta`-class, `F_x` subscripts, juxtaposition → implicitMultiply), CAS `Simplifier` (n-ary flatten → canonical sort → exact fold → like-term collect; never auto-distributes), and `Equation` moves. Move rule (Equalynx): dragging a token across `=` applies its INVERSE to **both** sides — an addend subtracts from both, a NUMBER coefficient divides both (exact); same-side drop folds. `applying(dropped, asRole: .factor, to:)` multiplies both sides and returns `.choice([factored, distributed])` when those differ (chips). `Projection.swift`: an author `ComponentTable` (parsed eagerly) lets `Equation.projected(onto:components:)` substitute each vector → its scalar component (`\vec F = m\vec g + \vec T` → x: `F_x = T\cos\theta`, y: `0 = mg + T\sin\theta`). `matches()` is simplifier-based (so `2x` matches `x·2`).

`Sources/Physica/Equation/`: each token is a `TextEntity` carrying a `TokenComponent` (its `DisplayToken` + move address); glyphs come from a **synchronous** `TokenGlyphProvider` (D5 — MathJax `tex2svg` is sync after one `load()`): `FontTokenGlyphProvider` (renders `token.value`), `StubTokenGlyphProvider` (unit boxes, tests), `MathJaxTokenProvider` (per-token SVG, cached; web). `MathSVG.measuredGlyphs` is the baseline-relative variant (parses the root `vertical-align: -Nex`, 0.441 em/ex) so a row's tokens share a baseline; `glyphs(fromSVG:)` (bounds-centered) is unchanged. `EquationRow` baseline-aligns tokens with glue/op/equals gaps and records `equalsAnchorX`; `EquationEntity` stacks rows and x-aligns every `=` on the first row's (continuation rows drop the LHS but keep `=`); only the last row is editable. `GlyphSlice.makeLiteral(_:)` clones a slice into a draggable `LiteralEntity` that follows the source's world center until grabbed. `PlaceholderEquationEntity` is a drop target that matches its `target` via `matches()`. `EquationGame` installs ONE drop target on the equation: it reads the move address off the dragged proxy's `TokenComponent`, picks the side by the drop's x vs the `=`'s world x, and runs `movingTerm`/`applying`/`projected`; `.resolved` appends a row, `.choice` raises chips (`drag.isEnabled = false` while up), reaching `goal` (`matches`) highlights + fires `onWin`.

### Physics

Hamiltonian/momentum form: state is (transform, p, L); velocities are derived (`ω = R I⁻¹ Rᵀ L`), integrated symplectically at a fixed 1/240 step with an accumulator (`HamiltonianSystem.step(_:in:)` is public for deterministic tests). Contacts are SDF surface-sample based, uniform across sphere/box/ellipsoid/torus. Gotcha: **restitution = min(A, B)** and the default is 0.4, so bounce tests must set restitution explicitly on the static body too. Physics entities should be scene roots.

### JavaScriptKit gotchas (WASM subtree + PhysicsEngine; JSKit pinned to main @453b841)

- Heterogeneous descriptor dicts: `[String: JSValue]` + `.jsValue` — existential `[String: ConvertibleToJSValue]` doesn't conform; mixed literals need explicit `JSValue.number(...)`.
- `JSObject` dynamic methods need `!` (`global.requestAnimationFrame!`); ambiguous property chains need a type annotation (`let gpu: JSValue = navigator.gpu`).
- Await promises with the function form `JSPromise(...).value()` — the `.value` property trips sendability from @MainActor. Both live in the **JavaScriptEventLoop** module: any file using them needs `import JavaScriptEventLoop` (lenient member-import visibility can hide a missing import until files move between targets).
- JSClosure bodies: do work inside `MainActor.assumeIsolated { ... }` returning Void, then `return .undefined` outside (JSValue isn't Sendable).
- The BridgeJS plugin is configured in Package.swift but zero `@JS` is used — delete the plugin line if it ever breaks the build.

## Verifying renderer/web changes

`swift test` covers everything in the core (story player, drag, equation game are all host-tested via `scene.dispatch`/`seek`). For anything touching `Sources/Physica/WASM/` (Render/ or Web/), rebuild the wasm bundle and check visually: headless Chrome renders WebGPU on macOS via puppeteer-core with `--headless=new --use-angle=metal --enable-unsafe-webgpu` against the running bun server (screenshot the canvas at chosen timeline times). Story mode is the same drill against `/story.html` (assert the spacer count, that scrolling moves the HUD slide, and that ArrowDown advances it). `bun scripts/smoke.mjs` is the GPU-free sanity check that the bundle still boots — it has no DOM, so it always runs the pendulum path and must stay byte-identical.
